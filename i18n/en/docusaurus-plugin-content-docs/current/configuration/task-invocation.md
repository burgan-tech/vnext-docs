# Task Invocation Routing (TaskInvocation)

:::note
Translation pending — the Turkish page is the source of truth.
:::

Starting with v0.0.94, the Orchestration host runs `http`, `daprservice`, `soap` and `statestore` tasks in-process by default under `Workflow:TaskInvocation` (`DefaultMode: "Remote"` plus per-type `Modes`, `MaxConnectionsPerServer` 50 and `LocalInvocationTimeoutSeconds` 60 as code defaults); the router resolves a task-definition override stub, then the per-type entry, then `DefaultMode`, and always degrades to Remote when no local invoker exists, while `Custom` is rejected at startup. Changes take effect only after an Orchestration restart, local `statestore` (which, since v0.0.99, also carries Cache-Aside cache I/O — the `cacheaside` mode and `LocalCacheAsideTaskInvoker` were removed, so drop `Modes:cacheaside` from configuration) requires the Dapr `state` component on the orchestrator (custom `storeName` components must be scoped to it), the type-22 External HTTP task is deprecated, and errorBoundary rules using `errorTypes` now match on the remote path as well. <sup>New</sup> v0.0.100 — for a task resolved Remote, the Orchestration → Execution call is always Dapr HTTP service invocation (`POST api/v1/execution/invoke/{type}/{key}`): the opt-in gRPC transport was removed, `ExecutionApi:Transport` is no longer read (a leftover `grpc` is ignored) and `Kestrel:GrpcPort` is gone. Only an environment that had switched `ExecutionApi__Transport=grpc`, the Execution sidecar's `app-protocol` to `grpc` and its app port to the gRPC port is affected; it must return the Execution sidecar to `app-protocol: http`. Helm chart 1.0.123 drops `execution.grpcPort`, `Kestrel__GrpcPort` and `ExecutionApi__Transport`; `execution.dapr.protocol` stays `"http"`. Dapr sidecar gRPC (sidecar-to-sidecar, the app's state/lock/pub-sub calls) and OTLP gRPC are unaffected.

<sup>New</sup> v0.0.102 — the named HTTP clients every `http`/`soap` task (and the deprecated type-22 task) sends through are built on a pooled `SocketsHttpHandler` by one shared factory on both hosts, with an infinite handler lifetime (before, `IHttpClientFactory` rotated the handler every two minutes and discarded warm TCP+TLS connections). Connection retirement is per connection: `Workflow:TaskInvocation:PooledConnectionLifetimeSeconds` (default 600, bounds how long a DNS or gateway change can go unnoticed) and `Workflow:TaskInvocation:PooledConnectionIdleTimeoutSeconds` (default 120, keep it below the gateway's keep-alive timeout) join `MaxConnectionsPerServer` (default 50) on Orchestration. The Execution host reads the same three dials from its own `WorkflowHttpClient` section with the same defaults (its cap was a hardcoded 10, now 50); an environment that overrides one host's cap should override the other to match before reverting a hot single-target type to Remote. `daprbinding` (type 2) now has a local invoker; it is not in the shipped `Modes` (stays Remote) — set `"daprbinding": "Local"` for flows that read, list or delete `x-storage` objects, whose components live on the orchestration sidecar (see [File Fields](/docs/how-to/file-fields)).

See the Turkish page for the timeout layering, the cost of the local path, the `vnext.task.invocation.mode` span tag and how to revert a type to Remote.
