## 2. Doküman bölümleri ve sidebars taksonomisi

Docusaurus'ta **her doküman plugini kendi sidebar dosyasına** sahiptir; sidebar navigasyonun tek
doğruluk kaynağıdır (`AGENTS.md:51`).

- **`sidebars.ts` (Technical) — MANUEL:** ağaç elle yazılır (`sidebars.ts:3-131`). Üst düğümler:
  Getting Started, Deployment, Developer Tools, Workflow (Tasks + Functions alt kategorileri),
  Core Concepts, Practical Guides (Pseudo UI alt kategorisi), Yapılandırma, API Reference.
- **`sidebars-architecture.ts` — MANUEL:** Overview / Domain Model / Data / Patterns
  (`sidebars-architecture.ts:4-40`).
- **`sidebars-business.ts` — AUTOGENERATED:** `[{ type: 'autogenerated', dirName: '.' }]`
  (`sidebars-business.ts:4`) → TOC klasör yapısından + `sidebar_position` frontmatter'ından üretilir.
- **`sidebars-product.ts` — AUTOGENERATED:** aynı desen (`sidebars-product.ts:4`).

**Önemli sonuç:** manuel bölümlerde (docs/architecture) bir sayfanın yayınlanması için sidebar'a
elle eklenmesi gerekir; eklenmezse sayfa URL'den erişilebilir ama navigasyonda görünmez (orphan —
bkz. bilinen-tuzaklar). Autogenerated bölümlerde (business/product) klasöre eklenen her md
otomatik TOC'a girer.

## 3. Bir konuyu bulma algoritması (lookup çözümü)

"X konusu hangi md'de, hangi bölümde":
1. **Intent → bölüm eşle:** teknik/geliştirme → `docs/`; mimari → `architecture/`; iş değeri/terim →
   `business/`; ürün/vizyon/roadmap → `product/`; sürüm/breaking/migration → ilgili `blog*`.
2. **Manuel bölüm ise sidebar'ı oku** (`sidebars.ts` / `sidebars-architecture.ts`) — konunun
   sidebar id'sini bul. Autogenerated bölümde klasörü listele.
3. **id → dosya:** `grep -rn "^id: <deger>" <bölüm>/`; explicit `id` yoksa dosya adı (bölüm köküne
   göreli, `.md`'siz) = id. Örnek çözümler (doğrulandı):
   - `sidebars.ts:99` `how-to/view-consept/giris` → `docs/how-to/view-consept/index.md`
     (`id: giris`, `docs/how-to/view-consept/index.md:2`).
   - `sidebars.ts:101` `tasarimci-rehberi` → `docs/how-to/view-consept/designer-guide.md`
     (`id: tasarimci-rehberi`, `designer-guide.md:2`).
4. **Konu adıyla teyit:** başlık/terim string'ini bölüm dizinine sınırlı grep'le, `dosya:satır`
   ile alıntıla.
5. **İlişkili sayfalar:** md içi linkleri takip et (glossary sayfası her terimi ilgili component
   sayfasına bağlar — `business/glossary/index.md:21,31,41,51`).
6. **Dil:** İngilizce için `i18n/en/docusaurus-plugin-content-docs{-plugin}/current/<göreli yol>`;
   yoksa tr kaynağını authoritative kabul et.

## 4. Dosya adlandırma & frontmatter kuralları
- **Slug:** kebab-case; Türkçe slug'lar Türkçe kalır (`view-consept`, `nasil-yapilir`) —
  İngilizce'ye çevrilmez (`AGENTS.md:42`, `AGENTS.md:73`).
- **Zorunlu frontmatter:** en az `id` + `title` + `sidebar_label` (`AGENTS.md:43-50`); pek çok
  sayfa `sidebar_position` ve `description` da taşır (örn. `docs/how-to/view-consept/index.md:2-6`).
  Bazı sayfalar `id` yerine `slug` kullanır (örn. `docs/intro.md:2` `slug: /intro`).
- **`id` çevrilmez, `title`/`sidebar_label` çevrilir** (`AGENTS.md:74`). Sidebar girdisi `id`'ye
  bağlanır — bu yüzden `id` ≠ dosya adı olabilir (§3.3, bilinen-tuzaklar).
- **Component referans sayfaları** (`docs/components/**`) sabit 6 parçalı şablon izler: kısa giriş
  → JSON şema örneği → alan tablosu → enum tabloları → örnek bileşenler (`vnext-example` linki) →
  Related (`AGENTS.md:56-67`). URL deseni `/docs/components/{type}` veya `/{group}/{subtype}`
  (`tasks/http`, `functions/built-in`) (`AGENTS.md:67`).
- **Blog dosyaları:** `YYYY-MM-DD-slug.md` (örn. `blog/2026-06-29-v0-0-66.md`), frontmatter
  `slug/title/authors/tags/date` (`blog/2026-06-29-v0-0-66.md:1-7`); yazarlar `authors.yml`.

## 5. Dil (i18n) yapısı
- **Varsayılan locale `tr`, ikincil `en`** (`docusaurus.config.ts:30-37`). Türkçe içerik doğrudan
  `docs/`, `architecture/`, `business/`, `product/` altındadır.
- **İngilizce ayna:** `i18n/en/docusaurus-plugin-content-docs{-plugin}/current/<göreli yol>`
  (`AGENTS.md:71-72`). Plugin dizin adları: `docusaurus-plugin-content-docs` (technical),
  `-docs-architecture`, `-docs-business`, `-docs-product`; tema metinleri
  `docusaurus-theme-classic`; UI string'leri `i18n/en/code.json`.
- **Kapsam KISMİ (doğrulandı 2026-07-02):** technical (~36 en dosyası) ve architecture (~12) iyi
  aynalanmış; **business** yalnızca `intro.md` (1 en vs 8 tr), **product** yalnızca `intro.md`
  (1 en vs 7 tr); **blog** için çevrilmiş yazı YOK (`i18n/en/docusaurus-plugin-content-blog/`
  yalnızca `options.json`). İngilizce bir konu ararken ayna yoksa tr authoritative'dir.

## 6. Build / doğrulama
- **Yerel geliştirme:** `npm install` + `npm run start` → `http://localhost:3000/vnext-docs/`
  (`README.md:15-21`).
- **Build:** `npm run build` her iki locale'i derler; kırık linklerde uyarır (`AGENTS.md:91-93`).
- **Kırık link politikası:** şu an `onBrokenLinks: 'warn'` / `onBrokenAnchors: 'warn'` —
  Phase R refactoring sırasında geçici; R9'da `'throw'`a dönecek (`docusaurus.config.ts:20-28`).
- **PR öncesi:** yeni sayfa doğru sidebar'da görünmeli, linkler 404 vermemeli, yeni bölüm eklendiyse
  `context7.json` kapsamalı, component sayfalarında 6 şablon bölümü bulunmalı (`AGENTS.md:89-95`).
- **Hosting/CI:** GitHub Pages + GitHub Actions (`README.md:31-34`); `editUrl` `main` branch'ine
  bakar (`docusaurus.config.ts:47`).
