## Overview

**v0.0.99** is a feature release, and it has breaking changes.

- **CacheAside** now runs its source as a real task, and its cache key can be a script. `keyExpression` and the `cacheaside` routing mode are removed ([#1053](https://github.com/burgan-tech/vnext/pull/1053)).
- **Field protection**: data schemas gain **`x-masking`** and **`x-encryption: encrypt`** (AES-256-GCM at rest, per-instance keys). `x-roles`, `x-masking` and `x-encryption` are now enforced on **every** instance read surface, including instance GET, list and the Get* tasks ([#1054](https://github.com/burgan-tech/vnext/pull/1054)).
- **Role grants**: one-level **`allOf` / `anyOf`** combinators. `authorize?queryRoles=true` now decides at the deepest SubFlow leaf only ([#1071](https://github.com/burgan-tech/vnext/pull/1071)).
- **Display labels**: the state, view, schema, master and catalog functions carry **labels**. Every transition describes its **target state** ([#1070](https://github.com/burgan-tech/vnext/pull/1070)).
- **Initial state**: a workflow no longer has to declare one. The instance starts at an implicit **`$start`** ([#1068](https://github.com/burgan-tech/vnext/pull/1068)).
- **Sync/async**: flows and transitions can pin the mode with **`executionType`** (`S` / `A`) ([#1037](https://github.com/burgan-tech/vnext/pull/1037)).
- **Parallel tasks**: task entries accept a **`variableKey`**, so the same task can run twice at one order ([#1072](https://github.com/burgan-tech/vnext/pull/1072)).
- **`instance-correlation`**: the `hierarchy` system function is replaced by a batched, cross-domain **`instance-correlation`** tree ([#1067](https://github.com/burgan-tech/vnext/pull/1067)).
- **Metrics**: new transition, state and function **metrics** endpoints ([#1030](https://github.com/burgan-tech/vnext/pull/1030)).

Component **schema 0.0.55** ships with this release, and every new keyword needs it.

## Features

### CacheAside runs its source as a task; script-typed cache key (#1053)

*Shipped in v0.0.99. ⚠️ Breaking.*

When the cache misses, the **source task now runs through its own executor**, with `sourceMapping` as its `IMapping` (InputHandler → invoke → OutputHandler). It is routed exactly as it would be in `onExecutionTasks`: same-domain trigger tasks use the in-process gateway, cross-domain ones go through discovery. This also fixes the empty-input source call (`/instances//data`).

- **Source task:** any task type except another CacheAside, which is rejected at execution time (log 10177).
- **What is cached:** the **`sourceMapping` output**. Without a mapping, the raw `data` is cached.
- **Task-level mapping:** its `OutputHandler` now runs on hits and misses alike. `context.Body.metadata` carries `CacheHit`, `Refreshed`, `Key`, `StoreName` and `ETag`.
- **`key`:** `string | ScriptCode`. A Dynamic Expresso expression, or a Roslyn class implementing `ICacheKeyMapping`, with `NAT` / `B64` / `REF` encoding. The default encoding is `B64`, so plain-text code needs `"encoding": "NAT"`. A non-blank script result overrides a key that the InputHandler set with `SetCacheKey`.
- **Cache I/O** goes through the shared state-store cache gateway and follows `Workflow:TaskInvocation:Modes.statestore`, like the StateStore task.
- **Removed:** `keyExpression`, the `cacheaside` wire type and the `Modes:cacheaside` routing key.

```json
"config": {
  "key": { "location": "dynamicExpresso", "encoding": "NAT", "code": "\"customer:\" + context.Instance.Key + \":profile\"" },
  "sourceTask": { "key": "get-customer-profile", "domain": "core", "version": "1.0.0" },
  "sourceMapping": { "location": "./src/CustomerProfileSourceMapping.csx", "code": "<base64>" },
  "ttlInSeconds": 300
}
```

Also fixed: a failed cache read or write under a sampled span threw instead of returning `CacheOk = false`. This affected the function response cache too. → [CacheAside Task](/docs/components/tasks/cache-aside)

### Field protection: `x-masking` and `x-encryption` (#1054)

*Shipped in v0.0.99.*

Two data-schema keywords control how a value is stored and how it is read. Both apply only to `string` properties, and a field takes at most one transform.

| Keyword | Effect |
|---|---|
| `x-masking: { operator: "mask", params: { keepFirst, keepLast, maskingChar } }` | Value is masked on read and keeps its length |
| `x-masking: { operator: "replace", params: { value } }` | Value is replaced on read |
| `x-encryption: { type: "hash", params: { algorithm: "sha256" \| "sha512" } }` | Digested **on write** with an HMAC keyed by a per-instance salt (`HASHED:SHA256:<hex>`). The plaintext is never stored |
| `x-encryption: { type: "encrypt" }` | Stored AES-256-GCM-encrypted in instance data (`ENCRYPTED:AES256:i1:…`) under a per-instance key |

```json
"iban": { "type": "string", "x-masking": { "operator": "mask", "params": { "keepFirst": 4, "keepLast": 2 },
          "roles": [ { "role": "morph-idm.ops", "grant": "allow" } ] } },
"tckn": { "type": "string", "x-encryption": { "type": "encrypt",
          "roles": [ { "role": "$InstanceStarter", "grant": "allow" } ] } }
```

`roles` on these two keywords is an **allow-only exemption list**: a matching caller sees the plain value, everyone else sees the transformed one. A `deny` grant and the `allOf` / `anyOf` combinators are rejected there.

Keys and salts are generated per instance on the first protected write and kept in a new **`InstanceSecrets`** table in the flow schema. They are cached in process only, never in Redis, and deleting the instance deletes its key.

**One guarded read path.** The following surfaces apply `x-roles` → `x-masking` → `x-encryption`:
- instance GET
- instance list
- the data function
- sync start/transition responses
- the `GetInstance` / `GetInstances` / `GetInstanceData` tasks

When the schema cannot be read, the response falls back to the stored form, never to plaintext.

**Scripts** see an encrypt field as its token. Code that needs the plain value calls `await context.Instance.DecryptAsync("path", ct)`, which opens only the instance's own data.

Every outbound task type now forwards the request's `sub`, `act_sub`, `position`, `client_id` and `role` headers wherever its mapping leaves them empty. A role that morph-idm resolved is never forwarded.

`x-encryption.type` `persisted` / `transport` (never enforced) are rejected at publish. → [Schema Definition](/docs/how-to/view-consept/schema-tanimi)

### `allOf` / `anyOf` role-grant combinators (#1071)

*Shipped in v0.0.99.*

A role grant is now exactly one of `role`, `allOf` or `anyOf`. Combinator children are `{ "role" }` only, one level deep. Combinators work in:
- transition `roles`
- workflow and state `queryRoles`
- `availableIn`
- function `roles`
- long-poll `roles`
- SubFlow overrides
- schema `x-roles`

```json
"roles": [
  { "allOf": [ { "role": "morph-idm.officer" }, { "role": "$user.$.context.Instance.Data.branchManager" } ], "grant": "allow" },
  { "anyOf": [ { "role": "morph-idm.auditor" }, { "role": "morph-idm.risk" } ], "grant": "deny" }
]
```

Evaluation uses three-valued logic shared by every surface. A role-bound leaf is *Unknown* for a role-less caller. A deny fires on Yes or Unknown, and an allow admits only on Yes. Plain single-role grants behave exactly as before.

Publish now rejects malformed `x-roles` entries and function `roles` with a malformed dynamic path. Previously these were silently inert. → [Authorization](/docs/concepts/authorization)

### Labels and the target state on read surfaces (#1070)

*Shipped in v0.0.99.*

Until now clients rendered internal keys (`to-3`, `sub-done`) or kept their own key-to-label table. Every read surface now carries the definition's labels, as the full `[{ language, label }]` list for every language:

- **State function.** Top level gains `stateSubType` and `stateLabels`. Every `transitions[]` entry, scheduled ones included, gains `labels` and `target { key, stateType, stateSubType, labels, subFlow }`, with `$self` resolved. The `timeout` block's `target` becomes the same object.
- **View, schema and master functions** return the component's `labels`.
- **Catalog:** each `functions[]` entry carries `labels`.
- **Load-time fix:** schema and function components' `attributes.labels` used to be dropped at load time. They are now read.

State function `ResponseShapeVersion` moves to **v14**. The schema and master function caches get their own shape version (**v2**). → [Built-in Functions](/docs/components/functions/built-in)

### Initial state is optional: implicit `$start` (#1068)

*Shipped in v0.0.99.*

A workflow may declare **at most one** Initial state (`stateType: 1`). When it declares none, the instance is born in the runtime's reserved, implicit **`$start`** state, and `startTransition.target` decides where it enters. `$start` has no tasks, view or transitions, and it is never listed in `states`.

Workflows that declare an Initial state behave exactly as before.

Publish now checks the start transition:
- `target` must name a declared state; `$self`, `$start` and an empty target are rejected.
- `$start` is reserved as a state key.

→ [Workflow](/docs/components/workflow)

### `executionType`: per-flow and per-transition sync/async (#1037)

*Shipped in v0.0.99.*

A flow (`attributes.executionType`) and any state, shared or start transition can declare `"executionType": "S"` (sync) or `"A"` (async).

**Precedence:** transition → flow → the caller's `?sync` query parameter. When a definition sets the mode, the query parameter is ignored. The response is `200` with the instance when the effective mode is sync, and `202` when it is async.

It does not apply to automatic transitions or SubFlow start/forward. Spans carry `vnext.execution.requested` and `vnext.execution.effective`, plus `vnext.execution.overridden=true` when a definition changed the caller's mode. → [Async / Sync](/docs/how-to/async-sync)

### `variableKey`: keep parallel task responses apart (#1072)

*Shipped in v0.0.99.*

Entries at one `order` run in parallel and are merged by response slot, which is `camelCase(task.key)`. When the same task was listed twice at one order (for example, two SubProcess starts), both wrote one slot, and the merge threw `Parallel tasks produced conflicting output for key '…'` on practically every run.

Task entries now accept an optional **`variableKey`** (`^[A-Za-z_][A-Za-z0-9_]*$`, max 100 characters). The effective slot is `variableKey ?? camelCase(task.key)`.

```json
{ "order": 2, "task": { "key": "start-child", "domain": "core", "version": "1.0.0", "flow": "sys-tasks" }, "variableKey": "primaryChild" },
{ "order": 2, "task": { "key": "start-child", "domain": "core", "version": "1.0.0", "flow": "sys-tasks" }, "variableKey": "secondaryChild" }
```

Publish rejects a slot collision: within one order for workflows, and across all `onExecutionTasks` for functions. Publish also rejects a malformed `variableKey`.

The parallel merge is now slot-aware. A later order that re-writes an earlier slot overwrites it, which used to throw too. → [Tasks](/docs/components/tasks)

### `instance-correlation` replaces `hierarchy` (#1067)

*Shipped in v0.0.99. ⚠️ Breaking.*

`GET /{domain}/workflows/{workflow}/instances/{instance}/functions/instance-correlation` returns the instance's SubFlow/SubProcess tree as `{ "root": node }`.

- **Node fields:** `currentState` (deepest active descendant), `ownState`, `subFlowType` (`S`/`P`), `terminalOutcome`, link fields and recursive `children[]`.
- **Batched walk:** one query per (domain, flow, version) hop, run in parallel. Partner-domain branches are fetched with one internal batch call each.
- **Incomplete subtrees** are marked `resolved: false`. The `unresolvedReason` is `depth-exceeded`, `hop-failed`, `instance-missing` or `hop-unsupported` (the partner runs an older runtime).
- **Bounds:** set by `Workflow:InstanceCorrelation` (`MaxDescentDepth` 20, `FanoutParallelism` 8, `MaxConcurrentHops` 32).

The old `hierarchy` function is **removed with no alias**: its path now returns 404. The MCP tool `get_instance_hierarchy` is now `get_instance_correlation`. → [Built-in Functions](/docs/components/functions/built-in)

### Transition, state and function metrics (#1030)

*Shipped in v0.0.99.*

- `GET …/instances/{instance}/transitions/{transitionKey}/metrics` and `…/states/{stateKey}/metrics` return every attempt, with its tasks (`hook`, `order`, status, duration, fault).
- `GET /{domain}/functions/{function}/metrics` and `GET /{domain}/workflows/{workflow}/functions/{function}/metrics` page through a domain-function execution journal (`page`, `pageSize` ≤ 100, `from`, `to`, `succeeded`). The response includes a `summary` with `count`, `p50Ms`, `p95Ms` and `failureRate`.
- **Function journaling is opt-in** per function with `attributes.executionLog: "E"`; `"D"` or absent records nothing. The journal is written asynchronously (`Workflow:FunctionExecutionJournal`: `QueueCapacity` 50000, `BatchSize` 1000) into the `sys_metrics` schema.
- The tasks function's items gain `hook` and `order`.

→ [Observability](/docs/how-to/observability)

## Behavior Changes

- **Instance GET and list prune and mask fields they used to return in full** (`x-roles`, `x-masking`, `x-encryption`). Encrypt fields are opened only for their `allow` roles ([#1054](https://github.com/burgan-tech/vnext/pull/1054)).
- **Get\* tasks read with their caller's visibility, not the system's.** A `GetInstance` / `GetInstances` / `GetInstanceData` task is evaluated as the credential it presents: its mapping headers, plus the caller's `sub` / `act_sub` / `position` / `client_id` / `role` where those are unset. `SystemRead` is removed ([#1054](https://github.com/burgan-tech/vnext/pull/1054)).
- **Credential headers are forwarded on every outbound task type** where the mapping leaves them empty ([#1054](https://github.com/burgan-tech/vnext/pull/1054)).
- **`authorize?queryRoles=true` is leaf-only.** Inside a SubFlow it decides on the parent-stamped override, else the leaf state's `queryRoles`, else the leaf workflow's. The root/intermediate AND is removed. This **loosens** access where a root declares `queryRoles` but the leaf has none ([#1071](https://github.com/burgan-tech/vnext/pull/1071)).
- **A role-less caller no longer matches an allow `$role.` grant** whose path resolves to `""` ([#1071](https://github.com/burgan-tech/vnext/pull/1071)).
- **New publish rejections:**
  - two Initial states, or a `$start` state key
  - an empty, `$self` or undeclared start target
  - a same-order slot collision or a malformed `variableKey`
  - malformed `x-roles` / function role paths
  - field-protection rule violations
  - `allowedAssemblies` names the runtime cannot resolve, even with the sandbox disabled ([#1069](https://github.com/burgan-tech/vnext/pull/1069))
- **`timeout.target` on the state function is an object** (`target.key`), no longer a string ([#1070](https://github.com/burgan-tech/vnext/pull/1070)).
- **Cache keys re-key once at deploy:**
  - state function shape v14
  - schema/master v2
  - data function generation v3
  - `CallerScopeHash` now includes `sub`

  Expect one round of `200`s instead of `304`s.

Each item and its migration steps are documented in the [v0.0.99 breaking changes announcement](/blog/breaking-changes/breaking-changes-v0-0-99).

## Fixes

- **`X-Request-Id` reaches the task target.** Since v0.0.80 a value set in a task's headers or input mapping was dropped as a reserved trace header, and nothing was sent in its place. OHVPS/BKM calls failed with `400 TR.OHVPS.Resource.InvalidFormat`. The header is now fill-if-absent: a non-empty mapping value wins, otherwise vNext's own request id is sent. An API that needs a UUID unique per call should set `Guid.NewGuid()` in the mapping ([#1059](https://github.com/burgan-tech/vnext/pull/1059)).
- **`context.Incident` sees the loaded incident.** Since v0.0.93, a mapping running inside error-boundary handling saw `HasActiveIncident = true` but `ActiveIncident = null` and `TotalIncidentCount = 0`. The upward `InstanceSubFaultedEvent` payload had the same gap ([#1060](https://github.com/burgan-tech/vnext/pull/1060)).
- **Large async transition bodies no longer strand the instance Busy.** The Dapr scheduler is now armed by reference to the job row (Aether 1.0.43) instead of carrying the body. A body over ~2 MiB used to stall the arm. The limit is now Kestrel's `MaxRequestBodySize` (10 MB, `413`), and an arm failure falls back to the outbox ([#1067](https://github.com/burgan-tech/vnext/pull/1067)).
- **`System.ObjectModel` is in the sandbox baseline.** Before this, a `foreach` over an `ExpandoObject` failed with CS0012 ([#1067](https://github.com/burgan-tech/vnext/pull/1067)).
- **`allowedAssemblies` is checked at publish.** An unresolvable name used to be dropped silently, and the script then failed mid-transition (CS0012 / CS1069). Publish now returns `400` and names the exact field ([#1069](https://github.com/burgan-tech/vnext/pull/1069)).
- **Telemetry:** failures are recorded on the spans that own them ([#1049](https://github.com/burgan-tech/vnext/pull/1049)).
- **SubFlow performance:** the no-op settlement at intermediate levels of a forward chain is skipped ([#1040](https://github.com/burgan-tech/vnext/pull/1040)), and sub-item lock contention on the `sub:state-changed` channel is reduced ([#1041](https://github.com/burgan-tech/vnext/pull/1041)).
- **`vnext-meta`** version fields aligned with the released images 0.0.88–0.0.97 ([#1038](https://github.com/burgan-tech/vnext/pull/1038), [#1039](https://github.com/burgan-tech/vnext/pull/1039)), and `deprecations.json` parses again ([#1070](https://github.com/burgan-tech/vnext/pull/1070)).

## Configuration Updates

Configuration for v0.0.99:

```json
{
  "runtimeVersion": "0.0.99",
  "schemaVersion": "0.0.55"
}
```

> **Note:** Schema **0.0.55** is required for `x-masking`, `x-encryption: encrypt`, `allOf` / `anyOf`, Initial-less workflows, `variableKey`, `executionType`, `executionLog` and the new CacheAside `key`. Domains validating with 0.0.54 reject them. Release the schema before publishing components that use them.

**New settings:**

| Section | Keys (defaults) |
|---|---|
| `SchemaMasking` | `Enabled` (true) |
| `SchemaEncryption` | `EncryptWrites` (true), `SecretCacheEntries` (100000), `SecretCacheSlidingMinutes` (30) |
| `Workflow:InstanceCorrelation` | `MaxDescentDepth` (20), `FanoutParallelism` (8), `MaxConcurrentHops` (32) |
| `Workflow:FunctionExecutionJournal` | `QueueCapacity` (50000), `BatchSize` (1000) |

**Removed:** `Workflow:TaskInvocation:Modes:cacheaside`. Delete it from environment config.

**Database migrations:**
- `AddInstanceSecrets` (per flow schema, FK to `Instances`, cascade delete)
- `AddInstanceTaskTriggerAndOrderColumns`
- `MetricsDb/AddFunctionExecutionsJournal` (`sys_metrics`)

**Rollout:**
- **Async transition jobs:** a job armed by an upgraded pod but run by an old pod fails to deserialize. Deploy with a full stop/start, or enable the arming poller on one host.
- **Combinators:** author the first `allOf` / `anyOf` only after every pod runs v0.0.99, including every domain that stamps overrides onto this one. Do not binary-downgrade once combinators are published.
- **CacheAside:** entries written by an older version hold raw values and are read back until their TTL expires.

**Container images:** published at tag `0.0.99` under `ghcr.io/burgan-tech/vnext/*`, Cosign-signed (keyless OIDC) with SBOM + provenance. Immutable digests are listed in the [v0.0.99 GitHub release](https://github.com/burgan-tech/vnext/releases/tag/v0.0.99).

## Summary

- **CacheAside** ⚠️: the source runs as a task, `sourceMapping` shapes what is cached, and `key` is a string or a script. `keyExpression` and `Modes:cacheaside` are removed.
- **Field protection:** `x-masking` (`mask` / `replace`) and `x-encryption` (`hash` on write, `encrypt` at rest) with allow-only exemption roles. They are enforced on instance GET/list, the data function, sync responses and the Get* tasks ⚠️. Scripts use `DecryptAsync`.
- **Role grants:** `allOf` / `anyOf` with three-valued evaluation. `authorize?queryRoles=true` is leaf-only ⚠️.
- **Labels:** every read surface carries them, and transitions describe their target state. `timeout.target` is an object ⚠️.
- **Initial state** is optional, via implicit `$start`. Start-target validation is tightened.
- **`executionType` `S` / `A`** overrides the `sync` query parameter.
- **`variableKey`** lets the same task run in parallel at one order. The merge is slot-aware.
- **`instance-correlation`** replaces `hierarchy` ⚠️. It is batched, parallel and cross-domain.
- **Metrics** endpoints cover transitions, states and functions. Function journaling is opt-in with `executionLog: "E"`.
- **Fixes:** `X-Request-Id` forwarding, `context.Incident`, large async bodies, sandbox `System.ObjectModel`, `allowedAssemblies` at publish.
- **Schema** moves to **0.0.55**.
