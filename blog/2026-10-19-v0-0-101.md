## Overview

**v0.0.101** is a container-image release with a single change: the runtime images now ship **GSSAPI** and **ICU** ([#1115](https://github.com/burgan-tech/vnext/pull/1115)). There are no runtime code changes, and nothing behaves differently with the default configuration. Component **schema 0.0.56** is unchanged.

## Fixes

### GSSAPI and ICU in the runtime images (#1115)

*Shipped in v0.0.101.*

**GSSAPI.** Npgsql probes GSSAPI on every connection (`GssEncryptionMode=Prefer` by default). The Alpine images had no Kerberos library, so every Alpine host printed `Cannot load library libgssapi_krb5.so.2` at startup. The line was harmless: the connection always succeeded. On OpenShift, however, it was mistaken for the DbMigrator failure.
- The Alpine images (orchestration, inbox, outbox, db-migrator) now install `krb5-libs`.
- The Execution image (Ubuntu noble) installs `libgssapi-krb5-2`.
- The startup line is gone.

**ICU.** The Alpine images had no ICU, so setting `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=0` made the runtime fail fast at startup. That setting is needed by `Microsoft.Data.SqlClient` used from a script plugin, which otherwise throws `Globalization Invariant Mode is not supported`.
- The four Alpine images now install `icu-libs` and `icu-data-full`. `icu-data-en` alone would silently format `tr-TR` values as English.
- The Execution image already had ICU (noble ships ICU 74).
- **The image default stays invariant.** The base image sets `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=true`, and Helm keeps `global.dotnetEnv.DOTNET_SYSTEM_GLOBALIZATION_INVARIANT: "1"`. Nothing changes until an operator sets the variable to `0`, which is only needed in an environment that uses SqlClient plugins.
- A script that uses SqlClient must also grant `System.ComponentModel.Primitives` next to `System.Data.Common` (`DbConnection` derives from `Component`); without it the compile fails with `CS0012`.

Each Alpine image grows by about 39 MB, almost all of it ICU locale data (orchestration 180 → 219 MB, db-migrator 182 → 221 MB).

## Configuration Updates

Configuration for v0.0.101:

```json
{
  "runtimeVersion": "0.0.101",
  "schemaVersion": "0.0.56"
}
```

> **Note:** Schema version is unchanged at **0.0.56**. There are no new settings, no migrations and no breaking changes.

**Container images:** published at tag `0.0.101` under `ghcr.io/burgan-tech/vnext/*`, Cosign-signed (keyless OIDC) with SBOM + provenance. Immutable digests are listed in the [v0.0.101 GitHub release](https://github.com/burgan-tech/vnext/releases/tag/v0.0.101).

## Summary

- **No more `libgssapi_krb5.so.2` startup line.** It was harmless; the images now carry the Kerberos library.
- **ICU in every image.** `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=0` now works, for SqlClient script plugins. The default stays invariant.
- **Schema** stays at **0.0.56**.
