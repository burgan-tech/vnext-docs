## Overview

**v0.0.98** is a hotfix release cut from the `v0.0.97` tag with a single fix cherry-picked, so nothing else merged on `master` since v0.0.97 ships in it. It restores the state function's **`interaction` block for a state that declares `interaction.longPoll.terminate: false`**. The block had been missing since v0.0.95, so clients never got the "keep long polling for `fallbackTimeoutSeconds`" directive for such a state ([#1051](https://github.com/burgan-tech/vnext/pull/1051), mirrored to `master` as [#1052](https://github.com/burgan-tech/vnext/pull/1052)). Component **schema 0.0.54** is unchanged.

## Fixes

### `interaction` block served again for a non-terminating long poll (#1051)

*Shipped in v0.0.98.*

v0.0.95 made the `interaction` block appear only while a long-poll acknowledge is outstanding (shape v11, [#1027](https://github.com/burgan-tech/vnext/pull/1027)). That condition was applied to **every** long poll. But only a state with `terminate: true` ever arms an acknowledge token. A state with `terminate: false` never pauses the pipeline, so in v0.0.95–v0.0.97 its block was suppressed entirely.

The condition now applies to `terminate: true` only.

| `interaction.longPoll.terminate` | When the block is served | `ack.href` |
|---|---|---|
| `true` | Only while the acknowledge is outstanding. Unchanged. | Present |
| `false` | Whenever the instance is in the declaring state and the caller passes the gate (`rule`, else `roles`) | **Absent**. Nothing is armed server-side, so there is nothing to acknowledge |

```json
"interaction": { "terminateLongPoll": false, "fallbackTimeoutSeconds": 120 }
```

**Client contract:** for `terminate: false`, `fallbackTimeoutSeconds` replaces the client's default long-poll window. For example, with a default of 60 s and a declared value of 120 s, the client polls for 120 s. The acknowledge endpoint and `authorize?ack=true` act only on an armed token, so they are still `terminate: true`-only.

`StateFunctionCache.ResponseShapeVersion` moves from **v12 to v13**. A client parked behind a `304` gets a `200` once and picks up the restored block.

See [State Interaction (Long Poll)](/docs/components/workflow) for the full model.

## Summary

- **`terminate: false` states return their `interaction` block again.** It has no `ack`, and `fallbackTimeoutSeconds` sets the client's long-poll window. This had been broken since v0.0.95.
- **`terminate: true` is unchanged.** The block and `ack.href` are served only while the acknowledge is outstanding.
- **State function `ResponseShapeVersion` v13.** Cached ETags refresh once.
- **Schema** stays at **0.0.54**.
