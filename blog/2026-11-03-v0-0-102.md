## Overview

**v0.0.102** is a feature release, and it has breaking changes.

- **Flow default version (Publish ≠ Activate)**: a flow can pin its default version in the `sys-version-registry` system flow. Versionless and partial requests resolve to that default, and newer published versions stay pending until they are requested explicitly. Start responses now carry the resolved `flowVersion` ([#1130](https://github.com/burgan-tech/vnext/pull/1130)).
- **Row security**: `attributes.rowSecurity` declares role-keyed, deny-by-default row rules for the instance list, the single instance GET and the GetInstances / GetInstance tasks. ⚠️ For **every** flow, those reads now fail when the flow definition cannot be loaded ([#1134](https://github.com/burgan-tech/vnext/pull/1134)).
- **Automatic transition priority**: an optional `priority` orders a state's automatic transitions ([#1140](https://github.com/burgan-tech/vnext/pull/1140)).
- **File fields (`x-storage`)**: streamed uploads, verified reads, file processing in scripts, DaprBinding task responses and raw byte function bodies ([#1144](https://github.com/burgan-tech/vnext/pull/1144)).
- **SubFlow carried headers**: the headers of the request that settled a child reach the parent's output mapping and, by default, the parent's resume ([#1141](https://github.com/burgan-tech/vnext/pull/1141)).
- **Performance**: fewer database round-trips, commits and lock waits per hop, and pooled HTTP task clients ([#1152](https://github.com/burgan-tech/vnext/pull/1152)).
- **Schema**: the `x-validation` **`remote`** rule (vnext-schema 0.0.57).

Component **schema 0.0.58** ships with this release. `rowSecurity`, transition `priority` and `x-storage.transport` need it.

## Features

### Flow default version: Publish ≠ Activate (#1130)

*Shipped in v0.0.102.*

Publishing a flow version no longer activates it when the flow has a default version. The default-version pointer lives in the `sys-version-registry` system flow. Its instance key is the flow key, and its data is `{ "type": "Flow", "defaultVersion": …, "reason": … }`.

| Pin mode | `defaultVersion` | Effective default |
|---|---|---|
| Exact | `2.1.0` | that version |
| Package build | `2.1.0-pkg.1.0.168` | that build (build metadata ignored) |
| Minor line | `2.1` | the highest `2.1.x`; hotfixes advance it |
| Major line | `2` | the highest `2.x` |
| Automatic | `latest` | the latest published version, as before. `latest` is also how a pointer is cleared |

How requests resolve against the effective default:
- A versionless or `latest` request resolves to the effective default.
- A partial request (`2`, `2.1`) resolves to the best match at or below it.
- Newer versions stay **pending**. Only an explicit full (`-pkg.`) or artifact (`2.2.0`) request reaches them.

```http
POST /api/v1/{domain}/workflows/sys-version-registry/instances/start?sync=true
{ "key": "customer-onboarding", "attributes": { "type": "Flow", "defaultVersion": "2.1.0" } }

PATCH /api/v1/{domain}/workflows/sys-version-registry/instances/{id}/transitions/set-default?sync=true
{ "attributes": { "type": "Flow", "defaultVersion": "latest" } }
```

**New error codes:**
- `Instance:100051` (404): the request matches only pending versions.
- `Instance:100052` (409): the pointer matches no published version. Floating requests fail closed, and explicit requests are still served. A write of such a pointer is rejected too.
- `Instance:100053` (503): the registry cannot be read. It is transient and never negative-cached.

**What else changes:**
- A pointer change reaches every pod within about 5 seconds.
- SubFlow and SubProcess correlations store the child's **resolved** version, so a parent never re-resolves a floating reference to another definition than the one the child runs.
- Start responses carry the resolved **`flowVersion`**.
- Flows without a registry instance, `sys-*` flows and domains whose core package has no registry flow behave exactly as before.

→ [Flow Default Version](/docs/concepts/flow-default-version)

### Row security: `attributes.rowSecurity` (#1134)

*Shipped in v0.0.102. Experimental. ⚠️ Breaking (behaviour, every flow).*

A flow declares role-keyed row filters. They are written in the instance list filter language and can read `$.context.Headers`, `$.context.QueryParameters` and `$.context.CurrentUser` parameters. They can also use the `$InstanceStarter` / `$InstanceBehalfOfStarter` identity rules.

```json
"rowSecurity": {
  "rules": [
    { "roles": ["branch-staff"],
      "filter": { "attributes": { "branchCode": { "eq": "$.context.Headers.x-branch-code" } } } },
    { "roles": ["hq-auditor"] },
    { "roles": ["customer"],
      "filter": { "createdBy": { "eq": "$InstanceStarter" } } }
  ]
}
```

- **Deny by default.** There is no `default` rule. "Role X sees everything" is an explicit unfiltered rule. A flow without `rowSecurity` is not filtered.
- **Evaluation.** A caller sees the OR of the matched rules' filters, ANDed with the caller's own filter. A failed role resolution yields no rows. A failed parameter drops only the rule that reads it. Neither ever widens the result.
- **Covered reads:**
  - the public instance list, including `groupBy` and aggregations;
  - the single instance GET (an excluded instance answers the same 404 as a missing one);
  - the GetInstances / GetInstance tasks, same- and cross-domain.
- **Rule set.** The flow's default version (registry pointer) when set, else the latest, for instances of every version.
- **Publish.** `RS-E*` errors reject the publish. `RS-W*` warnings are logged only.

Every other read is unfiltered; see [Known Issues](#known-issues).

→ [Row Security](/docs/concepts/row-security), [Workflow](/docs/components/workflow)

### Automatic transition priority (#1140)

*Shipped in v0.0.102.*

An automatic transition can declare an optional integer **`priority`** (minimum 1).

- The Auto step evaluates a state's automatic transitions by `priority` ascending, then in declaration order. The first satisfied rule wins.
- A transition without `priority` counts as **100**.
- The DefaultAutoTransition (`triggerKind: 10`) is always evaluated last and cannot carry a priority.
- Evaluation is sequential, so cheap and likely rules belong at a low number. A rule that throws fails the step, and the rules after it are not evaluated.

```json
"transitions": [
  { "key": "to-low",  "target": "low",  "triggerType": 1, "priority": 30, "rule": { "...": "..." } },
  { "key": "to-high", "target": "high", "triggerType": 1, "priority": 10, "rule": { "...": "..." } },
  { "key": "to-fallback", "target": "fallback", "triggerType": 1, "triggerKind": 10 }
]
```

`to-high` is evaluated first even though it is declared second.

Publish rejects a `priority` below 1, and a `priority` on a manual, shared or start transition or on the DefaultAutoTransition. Publish warns when automatic transitions of a state share an effective priority and at least one of them declares it. → [Workflow](/docs/components/workflow)

### File fields: streaming, verified reads and file processing (#1144)

*Shipped in v0.0.102.*

**Streamed uploads.** `x-storage.transport` chooses how a client sends the bytes: `inline` (default, base64 in the JSON body), `stream` or `any`.
- For a `stream` / `any` field, `POST /api/v1/{domain}/workflows/{flow}/files?path=&name=` takes the raw body (no JSON, no base64), with `Content-Type` and a required `Content-Length`.
- The runtime stores the body through the field's Dapr binding and answers **201** with a single-use ticket: `file`, `component`, `path`, `name`, `mimeType`, `size`, `eTag`, `expiresAt`.
- A start or transition claims the ticket by sending `{ "file": "<id>" }` at the same path. Two concurrent claims cannot both succeed.
- A `stream`-only field refuses inline content from a client (400 `Instance:100048`). Above `FileStorage:Upload:MaxBytes` the upload answers 413.

**Verified reads.** Every read (`functions/file`, `internal/file`, `GetFileAsync`) checks the stored bytes against the handle's `size` and sha256 `eTag`.
- An object that a Dapr 1.17+ `bindings.aws.s3` stored `aws-chunked` framed is served as the original.
- Anything else answers **503** `Instance:100047` instead of a corrupt body.
- Files above 4 MB now read back. The Dapr client no longer caps a received message at gRPC's 4 MB default; such reads used to answer 503.

**File processing in scripts.**
- The sandbox allows the in-memory `System.IO` stream types and the `System.IO.Compression` streams. `File`, `FileStream`, `Directory`, `Path` and the rest of `System.IO` stay banned.
- `ScriptFile.OpenRead()` opens a read-only stream on a file.
- `ScriptBase.PutFileAsync(…)` stores a processed file and returns its handle.
- `ScriptBase.FileObjectKey(file)` names the object key for a DaprBinding task.

**DaprBinding task responses.**
- A DaprBinding task returns the binding's answer to its output mapping. `Data` is the body as JSON, text or base64 (`Metadata.DataEncoding`), and `Headers` holds the response metadata.
- Mappings set the per-call shape with `SetOperation` / `SetData` / `SetMetadata`. A flow can therefore delete, read or list its own objects; the runtime has no delete endpoint.
- `Workflow:TaskInvocation:Modes:daprbinding = Local` runs the task from the orchestration sidecar, where `x-storage` components live.

**Raw byte function bodies.** A `rawResponse` function whose output `Data` is a `byte[]` or a `ScriptFile` answers the bytes, with `Content-Length` and the right `Content-Type`.

→ [File Fields](/docs/how-to/file-fields), [Built-in Functions](/docs/components/functions/built-in), [Task Invocation](/docs/configuration/task-invocation)

### SubFlow carried headers (#1141)

*Shipped in v0.0.102. ⚠️ Behaviour change with defaults.*

When a SubFlow child settles (finish or exit, cancel, or a fault on a request), the headers of the request that settled it travel to the parent. They ride a new optional `CarriedHeaders` field on `instance.sub.completed` / `.faulted` / `.canceled`; the event contract change is additive.
- **Output mapping** (completion and fault): `context.Headers` holds them.
- **Resume** (completion, fault, cancel): by default the parent's resumed hop runs with them. That reaches auto conditions, onEntry tasks that forward the caller credential, and the next SubFlow's input mapping. `Actor` stays `System`.
- **What is carried:** every header except the deny floor (names containing `authorization`, `cookie`, `token`, `secret` or `session`, plus `AdditionalDenied`) and framework headers (`x-subflow-depth`, instance ids, `traceparent`, `content-*`, `dapr-*`, `grpc-*` …). `role` is always carried. Keys are lower-cased.
- **Nothing is carried** for a child settled by a timer, a timeout, a job-timeout recovery or a downward cascade.
- Header values are never logged; only counts are.

```csharp
// SubFlow OutputHandler on the parent
var sub = context.Headers?["sub"];            // identity of the user who finished the child
var lang = context.Headers?["accept-language"];
```

→ [Workflow](/docs/components/workflow), [SubFlow Overrides](/docs/how-to/subflow-overrides)

### Schema: `x-validation` remote rule (vnext-schema 0.0.57)

*Shipped in vnext-schema 0.0.57.*

The `remote` rule runs a backend function on the field value and reads the outcome from its response.

| Field | Type | Meaning |
|---|---|---|
| `source` | string | URN of the function the client calls. **Required** when `rule` is `remote` |
| `resultField` | string | response path whose truthy value means the value is valid |
| `messageField` | string | response path holding the message shown when the value is invalid |
| `trigger` | `change` \| `blur` | when the client calls the function |
| `debounce` | integer ≥ 0 | milliseconds to wait after the last change before calling |

→ [Schema Definition](/docs/how-to/view-consept/schema-tanimi)

## Performance

*Shipped in v0.0.102 ([#1152](https://github.com/burgan-tech/vnext/pull/1152)).*

Measured on a local `digital-investment` domain with OpenObserve traces:

| Metric | Before | After |
|---|---|---|
| Database round-trips per start | 105 | 83 |
| Write commits per start | 48 | 41 |
| Warm start | 290–340 ms | 235–280 ms |
| Inbox backup wait on a sub-item terminal lock | 154–169 ms | max 33–62 ms |
| 599 concurrent starts in 60 s (all completed), p50 | 445 ms | 374 ms |
| Database time per start, same load | 227 ms | 170 ms |

What changed:
- **InstanceData appends** take two round-trips instead of six. The statements are pipelined in two batches, and each still runs in order with its own snapshot.
- **Task journal:** one write per task, at completion. A hop that enters a Finish state with no OnEntry tasks saves the state once. The redundant `IsLatest` update is gone.
- **Sub-item terminal lock wait:** the default is 10 × 20 ms instead of 4 × 120 ms. The wait stops as soon as the other delivery has settled the work.
- **Pooled HTTP task clients** on both hosts. Warm TCP+TLS connections are no longer dropped every two minutes; before, a first call took 244 ms against 76 ms warm to one APISIX host.
- **`WorkflowExecution:Bookkeeping:AsynchronousCommit`** (opt-in): journal and transition-record writes commit without an fsync on the request path. A database crash can lose the last few hundred milliseconds of those rows only, never instance state, data or outbox. Measure before enabling.

## Behavior Changes

- **Instance reads fail on a flow lookup error** (`instance-read-fails-on-flow-lookup-error`) ⚠️. For every flow, the instance list, the single GET and the GetInstances / GetInstance tasks now look the flow up once (cached).
  - A lookup failure other than "no definition" fails the read with that error: `Instance:100052` (409), `Instance:100053` (503) or `Instance:100051`. The read logs warning 20509.
  - Before, the list served rows and GET did not look the flow up.

  ([#1134](https://github.com/burgan-tech/vnext/pull/1134))
- **Parent resume runs with the settling request's headers** (`subflow-resume-carried-headers`) ⚠️. Opt out with `Workflow__SubFlow__CarriedHeaders__ApplyToResume=false` ([#1141](https://github.com/burgan-tech/vnext/pull/1141)).
- **Automatic transition order** (`auto-transition-absent-trigger-kind-order`). An automatic transition with no `triggerKind` was evaluated before one with an explicit `triggerKind: 0`. Both now keep declaration order (after `priority`). Only a state that mixes the two and has more than one satisfiable rule can pick a different winner ([#1140](https://github.com/burgan-tech/vnext/pull/1140)).
- **File fields and scripts** ([#1144](https://github.com/burgan-tech/vnext/pull/1144)):
  - `file-read-integrity-503`: stored bytes that do not match the handle answer 503 `Instance:100047` instead of being served.
  - `script-sandbox-member-bans`: reflection by name, the non-generic `Activator` and `Environment.Exit` / `FailFast` / `SetEnvironmentVariable` no longer compile in scripts. None of them was found in any shipped domain package.
  - `function-raw-byte-array-body`: a `byte[]` raw function body is written as bytes, not as a quoted base64 JSON string.
  - `daprbinding-task-output-mapping-data`: a DaprBinding task's output mapping sees the binding's answer. An unmapped task still adds no instance data.
  - `file-offload-keeps-client-members`: the `x-storage` swap keeps the client's other members of the file node, such as `documentType`.
- **`functions/tasks` no longer lists a running task.** The journal row is written once, at completion, with its final status ([#1152](https://github.com/burgan-tech/vnext/pull/1152)).

Each item and its migration steps are documented in the [v0.0.102 breaking changes announcement](/blog/breaking-changes/breaking-changes-v0-0-102).

## Fixes

- **Interaction waits leave their parked Busy.** A Busy-subtype state with an `interaction` no longer stalls.
  - An armed timeout no longer blocks the automatic transition that `updateData` opens.
  - A firing timeout now takes the parked Busy over; before, it was refused and the instance stayed parked.
  - Instances that were already stuck had their timer consumed and do not move by themselves.

  ([#1128](https://github.com/burgan-tech/vnext/pull/1128))
- **Schemas without `$schema` are evaluated as Draft 2020-12.** Such a schema with `x-*` keywords (`x-storage`, `x-roles` …) published fine and then failed the first write with a 500. With `x-storage` the failure came after the files were offloaded. Declaring `$schema` stays the recommendation ([#1139](https://github.com/burgan-tech/vnext/pull/1139)).
- **S3 objects get their `Content-Type`.** The file store sent the media type under a metadata key that `bindings.aws.s3` does not read. New writes now carry the real type for direct S3 readers. `functions/file` was never affected, and existing objects keep their type ([#1137](https://github.com/burgan-tech/vnext/pull/1137)).
- **Superseded SubFlow state deliveries are dropped before the lock.** The duplicate `Correlation not found` Warnings described in [#1132](https://github.com/burgan-tech/vnext/issues/1132) are gone.
  - A child's last `sub:state-changed` (`Completed`) is no longer applied on top of the terminal event.
  - A late Inbox backup for a closed correlation no longer contends for the lock.
  - The orchestration host raises the `Failed to acquire lock` category to `Error`. This is a log-level change only and does not reduce contention.

  ([#1142](https://github.com/burgan-tech/vnext/pull/1142))

## Known Issues

- **`row-security-instance-surfaces-unfiltered`**: `rowSecurity` filters only the list, the single GET and the GetInstances / GetInstance tasks. Functions, transitions, view resolution and GetInstanceData read excluded instances by id. Do not treat it as an access boundary for an instance whose id the caller knows.
- **`subflow-carried-headers-denylist`**: carried headers use a denylist. A credential in a header such as `x-api-key` is carried unless it is listed in `AdditionalDenied` (exact names).
- **`dapr-s3-binding-frames-tls-uploads`**: Dapr 1.17+ `bindings.aws.s3` writes https uploads `aws-chunked` framed to a store that does not decode them. The runtime recovers them on read, but direct bucket readers see the frame.
- **`file-staged-upload-orphans`**: a streamed upload that nobody claims before its ticket expires leaves its object in the store. Use the store's lifecycle rules.
- **`script-sandbox-reflection-gaps`**: a few reflection members stay allowed because shipped packages use them. The analyzer guards against accidental misuse; isolation is the host's job.
- **`file-download-response-buffered-by-body-logging`**: Aether's body-logging middleware holds a downloaded file in memory once more. The fix belongs in Aether.

## Configuration Updates

Configuration for v0.0.102:

```json
{
  "runtimeVersion": "0.0.102",
  "schemaVersion": "0.0.58"
}
```

> **Note:** Schema **0.0.58** is required for `attributes.rowSecurity`, transition `priority` and `x-storage.transport`. The `x-validation` `remote` rule shipped in 0.0.57. Release the schema before publishing components that use them.

**New settings:**

| Section | Keys (defaults) |
|---|---|
| `Workflow:SubFlow:CarriedHeaders` | `Emit` (true), `ExposeToOutputMapping` (true), `ApplyToResume` (true), `AdditionalDenied` (`[]`), `MaxEntries` (64), `MaxValueLength` (4096) |
| `Workflow:TaskInvocation` (Orchestration) | `PooledConnectionLifetimeSeconds` (600), `PooledConnectionIdleTimeoutSeconds` (120; keep it below the gateway's keep-alive timeout), next to the existing `MaxConnectionsPerServer` (50) |
| `WorkflowHttpClient` (Execution) | `MaxConnectionsPerServer` (50; was a hardcoded 10), `PooledConnectionLifetimeSeconds` (600), `PooledConnectionIdleTimeoutSeconds` (120) |
| `WorkflowExecution:Bookkeeping` | `AsynchronousCommit` (false) |
| `FileStorage:Upload` | `MaxBytes` (67108864 = 64 MiB, the sidecar's `--max-body-size`; raise both together), `TicketTtlMinutes` (60) |
| `Workflow:TaskInvocation:Modes` | `daprbinding` can be set to `Local` to reach `x-storage` components (default stays `Remote`) |

**Changed default:** `WorkflowExecution:SubItemTerminalLockRetry` is now 10 attempts × 20 ms (`MaxAttempts`, `BaseDelayMilliseconds`); it was 4 × 120 ms.

**Database migrations:** none.

**Rollout:**
- **Check the default-version pointers before upgrading.** Every flow's `sys-version-registry` pointer must resolve to a published version (or be `latest`), and the registry must be reachable. Watch warning 20509 after the rollout.
- **Do not roll back below v0.0.102** for flows that declare `rowSecurity`, or for flows that rely on `priority`. An older runtime ignores both: it serves every row and evaluates automatic transitions in array order.
- **The component cache misses once.** Its keys gain a shape segment, so the first reads after the upgrade miss the cache.

**Requirements:**
- **Flow default version** needs vnext-core **v0.0.21** or later (npm: `@burgan-tech/vnext-core-runtime@0.0.21`, [release](https://github.com/burgan-tech/vnext-sys-flow/releases/tag/v0.0.21)), which ships `sys-version-registry`. A domain on an older core package behaves as Automatic.
- **Row security** needs a gateway that strips or overwrites the role header and every header a rule reads. Query parameters are client-controlled.

**Container images:** published at tag `0.0.102` under `ghcr.io/burgan-tech/vnext/*`, Cosign-signed (keyless OIDC) with SBOM + provenance. Immutable digests are listed in the [v0.0.102 GitHub release](https://github.com/burgan-tech/vnext/releases/tag/v0.0.102).

## Summary

- **Flow default version:** pin a flow's default in `sys-version-registry`; newer versions stay pending. Start responses carry `flowVersion`.
- **Row security** (experimental): deny-by-default row rules for the list, GET and GetInstance(s) tasks. ⚠️ Those reads now fail on a flow lookup error, for every flow.
- **Automatic transition priority:** lower first, absent = 100, default transition last.
- **File fields:** streamed uploads, verified reads, file processing in scripts, DaprBinding responses, raw byte bodies.
- **SubFlow carried headers** ⚠️: the parent's resume runs with the finisher's headers by default.
- **Performance:** 105 → 83 round-trips and 48 → 41 commits per start. `functions/tasks` no longer lists a running task.
- **Schema** moves to **0.0.58**.
