## Overview

**v0.0.100** is a feature release, and it has breaking changes.

- **Schema roles**: a schema component's `attributes.type` is now an optional **role**: `master`, `transition`, `function` or `component`. `x-encryption` gains a **`source`** (`runtime` at rest, `client` in transit). Publish validates **`x-filterOperators`** against the 14 declaration names. **`x-computed`** fields are evaluated by the runtime on every read surface ([#1091](https://github.com/burgan-tech/vnext/pull/1091)).
- **File fields (`x-storage`)**: file bytes go to a Dapr output binding (S3, MinIO, local storage), and the instance record keeps only a handle. Files are read back through the new **`functions/file`** endpoint ([#1085](https://github.com/burgan-tech/vnext/pull/1085)).
- **SubFlow transition proxy**: a parent with an active SubFlow forwards a transition to the leaf instead of queueing it ([#1085](https://github.com/burgan-tech/vnext/pull/1085)).
- **History mode**: `attributes.history: "none"` runs a one-shot flow without transition or task history and with a single data write ([#1082](https://github.com/burgan-tech/vnext/pull/1082)).
- **Kafka-ready topics**: every runtime topic is renamed to `vnext.{domain}.{environment}.*`. Helm chart **1.0.123** can run the runtime pub/sub on Kafka ([#1095](https://github.com/burgan-tech/vnext/pull/1095)).
- **Instance data history**: a paged, internal read of every data version ([#1079](https://github.com/burgan-tech/vnext/pull/1079)).
- **Script plugins** load once per process, and helper-less mappings can use them ([#1090](https://github.com/burgan-tech/vnext/pull/1090)).
- **Removed**: the opt-in Orchestration → Execution gRPC transport ([#1083](https://github.com/burgan-tech/vnext/pull/1083)).

Component **schema 0.0.56** ships with this release, and every new keyword needs it.

## Features

### Schema roles: `attributes.type` (#1091)

*Shipped in v0.0.100. ⚠️ Breaking for authoring tools.*

The schema component's `attributes.type` now names the **role** the schema plays. The role selects the vocabulary that decides which `x-*` keywords are valid.

| `attributes.type` | Role vocabulary | Used for |
|---|---|---|
| `master` | record | a flow's master (data) schema; the only role that allows `x-indexed` |
| `transition` | input | a transition body |
| `function` | input | a function `inputSchema` |
| `component` | component | an embedded view's own `dataSchema` |
| absent / `""` | none | a schema used in more than one role |

- **Schema package 0.0.56, CLI and Forge** refuse any other value, and any keyword written outside its role.
- **The runtime** publishes a legacy value (`schema`, `workflow`, `view`, `headers` …) with a **warning**. It will refuse it in a later release. A missing type is no longer a publish error.
- **Tool authors** must register the role vocabularies with `addVocabularies(ajv)` before compiling `schema-definition`.

→ [Schema Roles](/docs/concepts/schema-roles), [Schema](/docs/components/schema)

### `x-encryption` source: `runtime` or `client` (#1091)

*Shipped in v0.0.100.*

- **`source: "runtime"`** is the default. It keeps the at-rest behaviour of v0.0.99 (`hash`, `encrypt`).
- **`source: "client"`** declares in-transit encryption. The client seals the value before sending it. The runtime **never handles** such a field: it does not encrypt, mask or refuse filters, and it stores the value as sent. Members: `key` and `algorithm` (`HPKE-P256-SHA256-AES128GCM` | `RSA-OAEP-256`) are required; `into`, `encoding`, `nonce`, `envelope` and `purpose` are optional.

```json
"pin": {
  "type": "string",
  "x-encryption": {
    "source": "client",
    "key": "urn:client:context:read:device:memory:device.hpke.publicKey",
    "algorithm": "HPKE-P256-SHA256-AES128GCM",
    "into": "pinEnc"
  }
}
```

A master schema accepts both sources. Transition and function schemas accept `client` only, and component schemas accept neither. `x-encrypt`, the earlier proposal for this, never shipped. → [Schema Definition](/docs/how-to/view-consept/schema-tanimi)

### `x-computed`, evaluated by the runtime (#1091)

*Shipped in v0.0.100.*

A field marked `x-computed` with `evaluatedBy: "runtime"` is derived on every read surface and is **never stored**. The read surfaces are instance GET and list, the data function, data history, sync start/transition output, and the GetInstance / GetInstances / GetInstanceData tasks. The write path drops the field.

```json
"fullName": {
  "type": "string",
  "x-computed": {
    "evaluatedBy": "runtime",
    "cases": [
      { "when": { "field": "middleName", "operator": "isNotEmpty" },
        "join": { "fields": ["firstName", "middleName", "lastName"], "separator": " " } }
    ],
    "fallback": { "join": { "fields": ["firstName", "lastName"] } },
    "whenAbsent": "empty"
  }
}
```

- Each case, and the fallback, is either a `join` or an `arithmetic` (`add` / `subtract` / `multiply` / `divide`) over sibling properties. The first case whose `when` matches wins.
- The value is computed from the caller's **already shaped** view, after `x-roles`, `x-masking` and `x-encryption`. A computed field never reveals a field the caller cannot see.
- The field is always on; there is no flag. `evaluatedBy: "client"` is left to clients. `"server"` is refused as renamed to `"runtime"`.

→ [Schema Definition](/docs/how-to/view-consept/schema-tanimi)

### `x-filterOperators` validated at publish (#1091)

*Shipped in v0.0.100. ⚠️ Breaking.*

A schema declares the 14 declaration names: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `contains`, `startsWith`, `endsWith`, `in`, `nin`, `isNull`, `includes`.

Publish now refuses three kinds of values:
- **A query token** such as `ge`, `le`, `like` or `startswith`, with a message naming the declaration to use (`declare 'gte'`). Such a schema used to publish, and then every list filter on the field failed or never matched.
- **An unknown value.**
- **A duplicate.**

Query strings do not change: clients keep sending `ge`, `like` and the other query tokens. → [Instance Filtering](/docs/how-to/instance-filtering)

Schema 0.0.56 also adds `x-order`, `x-lov.items` / `imageField` and more `x-errorMessages` keys.

### File fields: `x-storage` (#1085)

*Shipped in v0.0.100.*

A master-schema field marked `"x-storage": { "binding": "<dapr output binding>" }` keeps its bytes in that binding.
- **Write:** the client sends base64 `content` once.
- **Store:** the runtime writes the bytes to the binding and replaces `content` with a **handle**: `component`, `file` (GUID), `name`, `mimeType`, `size`, `eTag`, `owner`. Instance data, the transition record, jobs and outbox events carry only the handle, so the bytes never reach PostgreSQL.
- **Read:** `GET|HEAD …/instances/{instance}/functions/file?file=<guid>`. The state's `queryRoles` is checked first (403), then `x-roles` of the field's path (404). The endpoint supports ETag / 304 and Range / 206, and serves active content types as `attachment`.
- **Scripts:** `ScriptBase.GetFileAsync(domain, flow, instance, file)`.
- **New error codes:** `Instance:100047` (store unavailable, 503), `100048` (invalid reference, 400), `100049` (not found, 404), `100050` (schema unavailable, 503).

On Helm, declare the binding under `global.blobStorageComponents`. It is scoped to the orchestrator.

→ [File Fields](/docs/how-to/file-fields), [Built-in Functions](/docs/components/functions/built-in), [Helm Chart](/docs/deployment/helm-chart)

### History mode: `attributes.history` (#1082)

*Shipped in v0.0.100.*

`"history": "none"` marks a **one-shot** flow:
- No `InstanceTransitions` or `InstanceTasks` rows are written.
- Instance data is buffered and written once: at Finish, at a SubFlow handoff, or on a fault.
- Omitting the field, or `"full"`, keeps full history.

Publish rejects a `none` flow that is not one-shot. That covers manual state transitions, shared transitions, cancel / exit / updateData, timeouts, long poll, Wizard / Suspended / Busy / Human states, and states that cannot reach a Finish state.

At runtime:
- A `none` parent's SubFlow child must be `none` too (`Instance:100044`).
- Retry answers 409 (`Instance:100045`).
- A stage that rests at a non-Finish state is faulted (`Instance:100046`).

→ [Workflow](/docs/components/workflow)

### Kafka pub/sub and runtime topic names (#1095)

*Shipped in v0.0.100. ⚠️ Breaking.*

Every runtime topic is now `vnext.{APP_DOMAIN}.{environment}.{event}.v{n}`, for example `vnext.core.production.instance.sub.completed.v1`. `{environment}` is `ASPNETCORE_ENVIRONMENT` lower-cased (`production` when unset). With this prefix, a Kafka ACL can grant each domain's user `vnext.{domain}.*`.

Helm chart **1.0.123** adds `global.dapr.pubsub.type: "kafka"`. It renders one `pubsub.kafka` component per host (orchestrator, execution, inbox, outbox) from `global.externalKafka`; the broadcast store stays on Redis.

The deployment pipeline sets each host's `consumerID` / `consumerGroup`. The consumer group each host joins must sit inside `vnext.{domain}.*`.

Domain-authored topics (`DaprPubSubTask.topic`, Subscriptions) are used verbatim and must follow the same prefix under Kafka. → [Helm Chart](/docs/deployment/helm-chart), [Event-Driven Workflows](/docs/how-to/event-driven-workflows)

### Instance data history (#1079)

*Shipped in v0.0.100. Internal.*

`GET …/instances/{instance}/data/history` returns one row per data write, newest first. It is paged (`page`, `pageSize` ≤ 100, `includeData`). `…/data/history/{rowId}` returns a single row.

Each row goes through the same exposure as the data function. The routes are hidden from Swagger but **not blocked**, so keep them off the public edge. They power the vNext Forge Instance Monitor. → [REST API](/docs/api-reference/rest-api)

### Script plugins load once per process (#1090)

*Shipped in v0.0.100.*

A plugin DLL in `Scripting:Sandbox:PluginDirectory` is loaded **once per process** and shared by every script and helper set: one copy, one connection pool.
- A **helper-less mapping** can now use a plugin type directly. Before, it compiled but failed at run time with `FileNotFoundException`.
- A DLL **added** after start is picked up without a restart (`Scripting:Sandbox:PluginRescanIntervalSeconds`, default 30). **Replacing** a loaded DLL needs a restart.
- Scripts get `ScriptContext.CancellationToken`.

→ [Scripting](/docs/configuration/scripting)

## Behavior Changes

- **SubFlow transition proxy.** When a parent has an active SubFlow, a forwardable transition is **forwarded unchanged to the leaf**. The parent no longer reserves the chain, flips Busy or schedules a job for it. The leaf validates the request, swaps files and takes its own Busy and job.
  - Leaf rejections (400 / 403 / 409) now reach the client **synchronously**; before, the parent answered 202.
  - A child that has completed, or does not exist yet, answers `409 InstanceBusy` on the parent; retry.
  - `updateData`, `cancel`, `exit`, timeouts and the parent's shared transitions still run on the parent.
  - Mixed-version domains need no action (deprecation `subflow-chain-reserve-claim`).

  ([#1085](https://github.com/burgan-tech/vnext/pull/1085))
- **New publish rejections:**
  - `x-filterOperators` query tokens, unknown values and duplicates
  - `x-computed.evaluatedBy: "server"`
  - a runtime `x-computed` on a transition, function or component schema, or next to `x-indexed` / `x-filterOperators` / `x-sortable` / `x-storage` / `x-roles` / `x-masking` / at-rest `x-encryption`
  - misplaced `x-storage`
  - a `history: "none"` flow that is not one-shot

  ([#1091](https://github.com/burgan-tech/vnext/pull/1091), [#1085](https://github.com/burgan-tech/vnext/pull/1085), [#1082](https://github.com/burgan-tech/vnext/pull/1082))
- **Legacy `attributes.type` values publish with a warning**, and a missing type publishes cleanly ([#1091](https://github.com/burgan-tech/vnext/pull/1091)).
- **`file` is a reserved system function name.** A custom function with the key `file` is shadowed ([#1085](https://github.com/burgan-tech/vnext/pull/1085)).
- **`IMapping.InputHandler` cannot stop a task.** The runtime never read its return value beyond the task audit record, and the docs now say so. Validate before the task, or throw ([#1087](https://github.com/burgan-tech/vnext/pull/1087)).

Each item and its migration steps are documented in the [v0.0.100 breaking changes announcement](/blog/breaking-changes/breaking-changes-v0-0-100).

## Removals

- **Orchestration → Execution gRPC transport** ([#1083](https://github.com/burgan-tech/vnext/pull/1083)). Orchestration always invokes Execution over Dapr HTTP service invocation.
  - `ExecutionApi:Transport` is no longer read; a leftover `grpc` is ignored.
  - `Kestrel:GrpcPort` is removed.
  - Only an environment that had switched the Execution sidecar to `app-protocol: grpc` must switch it back to `http`. None of the defaults ever did.

## Fixes

- **Plugins in helper-less script mappings.** They used to compile and then fail with `FileNotFoundException`. Every helper republish also used to load another copy of the driver ([#1090](https://github.com/burgan-tech/vnext/pull/1090)).
- **`vnext-meta`** versions for the v0.0.98 / v0.0.99 split are corrected ([#1075](https://github.com/burgan-tech/vnext/pull/1075)).

## Configuration Updates

Configuration for v0.0.100:

```json
{
  "runtimeVersion": "0.0.100",
  "schemaVersion": "0.0.56"
}
```

> **Note:** Schema **0.0.56** is required for `attributes.history`, `x-storage`, `x-computed`, `x-encryption.source`, `x-order`, `x-lov.items` and the `attributes.type` roles. Release the schema before publishing components that use them.

**New settings:**

| Section | Keys (defaults) |
|---|---|
| `FileStorage` | `KeyPrefix` (`""`; never change it after the first write), `AllowedBindings` (`[]`) |
| `Scripting:Sandbox` | `PluginRescanIntervalSeconds` (30) |

**Removed:** `ExecutionApi:Transport` (Orchestration), `Kestrel:GrpcPort` (Execution).

**Helm chart 1.0.123:**
- New: `global.dapr.pubsub.type` (`redis` | `kafka`), `global.externalKafka.*`, `global.blobStorageComponents`.
- Removed: `execution.grpcPort`, `Kestrel__GrpcPort`, `ExecutionApi__Transport`.

**Database migrations:** none.

**Rollout:**
- **Drain the outbox before rolling out.** Runtime topic names change, messages left on the old topics are not consumed, and outbox rows written before the upgrade keep the old topic name.
- **Under Kafka,** give every host a consumer group inside `vnext.{domain}.*` before switching `pubsub.type`.
- **Re-publish schemas** whose `x-filterOperators` use query tokens, after renaming them (`ge` → `gte`, `like` → `contains` …), together with or before the upgrade.

**Container images:** published at tag `0.0.100` under `ghcr.io/burgan-tech/vnext/*`, Cosign-signed (keyless OIDC) with SBOM + provenance. Immutable digests are listed in the [v0.0.100 GitHub release](https://github.com/burgan-tech/vnext/releases/tag/v0.0.100).

## Summary

- **Schema roles** ⚠️: `attributes.type` is `master` / `transition` / `function` / `component` or absent. The package refuses legacy values; the runtime warns.
- **`x-encryption.source`**: `runtime` at rest, `client` in transit (never handled by the runtime).
- **`x-computed`** is evaluated by the runtime on every read surface from the caller's view, and never stored.
- **`x-filterOperators`** ⚠️: declaration names only, checked at publish.
- **File fields:** `x-storage`, `functions/file`, `GetFileAsync` and a Helm blob storage component.
- **SubFlow transition proxy** ⚠️: leaf errors are now synchronous.
- **History mode:** `attributes.history: "none"` for one-shot flows.
- **Topics** ⚠️: `vnext.{domain}.{environment}.*`; drain the outbox. Helm can run the runtime pub/sub on Kafka.
- **Instance data history** for tooling (internal).
- **Script plugins** load once per process. gRPC transport removed.
- **Schema** moves to **0.0.56**.
