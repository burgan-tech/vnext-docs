v0.0.105 tek bir kırıcı değişiklik getiriyor: **rule-based `inputSchema`'sında eşleşen entry bulunamayan bir function, gövdeli isteği artık `400 Function:800006` ile reddediyor**. Önceden doğrulama atlanıyordu.

Bu sürüm component **schema 0.0.60** ile gelir. Etkilenen yalnızca, `inputSchema` listesindeki **bütün** entry'leri `rule` taşıyan (rule'suz son fallback entry'si olmayan) function'lardır. Listesi rule'suz bir entry ile biten veya tek bir şema kullanan function'lar için yapılacak bir şey yoktur.

## Breaking Changes

### 1. Eşleşmeyen rule-based `inputSchema` isteği reddeder (v0.0.105)

**Etkilenen Alan:** Function component'lerinde rule-based `inputSchema` (`[{ "rule", "schema" }]` listesi); function execute isteği ([vnext #1225](https://github.com/burgan-tech/vnext/pull/1225), deprecation `function-input-schema-no-match-accepts`)

**Önceki Davranış:**
- Function'ın `inputSchema` listesindeki entry'ler sırayla değerlendirilir, ilk eşleşen `rule`'un şeması istek gövdesini doğrulardı.
- Hiçbir entry eşleşmezse istek **doğrulanmadan** kabul edilir ve function çalışırdı. Bu, beklenmeyen bir çağıranın şema kontrolünü atlayabildiği açık (fail-open) bir yoldu.

**Yeni Davranış:**
- Bütün entry'leri `rule` taşıyan ve hiçbiri eşleşmeyen bir liste, gövde taşıyan isteği **`400 Function:800006`** (`FunctionInputSchemaNotMatched`) ile reddeder; function çalışmaz.
- Rule'suz entry fallback'tir: listede varsa (ve son sıradaysa) eşleşmeyen çağıranlar onunla doğrulanır.
- Aynı semantik v0.0.105'te transition'lara gelen `schemas` listesinde de geçerlidir (eşleşme yok → `400 Transition:100025`); transition'lar için bu yeni bir özellik olduğundan kırıcı değildir.
- Uyumluluk bayrağı yoktur.

**Migration:**
1. Domain'inizde `inputSchema`'sı liste olan function'ları bulun ve her listenin rule'suz bir entry ile bitip bitmediğine bakın.
2. Eşleşmeyen çağıranları kabul etmeye devam etmek istiyorsanız listenin **sonuna** rule'suz bir entry ekleyin. Eski davranışa en yakın seçenek, gevşek bir şema (ör. `type: object`) gösteren fallback'tir.
3. Eşleşmeyen çağıranları reddetmek istiyorsanız bir şey yapmayın; istemcilerin `400 Function:800006` yanıtını işlediğinden emin olun.
4. Domain paketinin `@burgan-tech/vnext-schema` sürümünü **0.0.60**'a yükseltip `npm run validate` çalıştırın.

Önce / sonra:

```json
// v0.0.104: kurumsal olmayan çağıran doğrulamasız geçerdi
"inputSchema": [
  { "rule": { "location": "./src/IsCorporate.csx", "code": "<base64>", "encoding": "B64" },
    "schema": { "key": "corporate-payload", "domain": "core", "flow": "sys-schemas", "version": "1.0.0" } }
]

// v0.0.105: eşleşmeyen çağıran rule'suz son entry ile doğrulanır
"inputSchema": [
  { "rule": { "location": "./src/IsCorporate.csx", "code": "<base64>", "encoding": "B64" },
    "schema": { "key": "corporate-payload", "domain": "core", "flow": "sys-schemas", "version": "1.0.0" } },
  { "schema": { "key": "retail-payload", "domain": "core", "flow": "sys-schemas", "version": "1.0.0" } }
]
```
