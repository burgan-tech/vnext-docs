v0.0.103 tek bir kırıcı değişiklik getiriyor: **Python Task (type `23`) artık inline script taşımıyor**. Task, domain'in kendi Python runtime image'ında kayıtlı bir handler'ın adını veriyor; Execution host'u Python'u ve `Python:*` ayarlarını tamamen bıraktı.

Bu sürüm component **schema 0.0.59** ile gelir. Python task kullanan domain'ler aşağıdaki adımları sürüm geçişinden **önce** tamamlamalıdır. Python task kullanmayan domain'ler için yapılacak bir şey yoktur.

## Breaking Changes

### 1. Python Task config'i inline script'ten handler referansına geçti (v0.0.103)

**Etkilenen Alan:** `attributes.type: "23"` olan task tanımları; Execution host'unun `Python:*` yapılandırması; Python task'ı çalıştıran ortamların deployment'ı ([vnext #1157](https://github.com/burgan-tech/vnext/pull/1157), migration `python-task-handler-contract`)

**Önceki Davranış:**
- Task, Python kodunu `config.script` (`NAT` / `B64`) içinde taşıyordu; kod `main(input)` giriş noktasını tanımlıyordu.
- `config.executionMode` (`pythonNet`, `process`, `container`) kodun Execution host'unda nasıl çalışacağını seçiyordu.
- Execution host `Python:*` bölümüyle yapılandırılıyordu (`Python:Enabled`, `Python:DefaultMode`, `Python:EnabledModes`, `Python:MaxTimeoutSeconds`, `Python:PythonNet:*`, `Python:Process:*`, `Python:Container:*`…). Paket seti Execution image'ında hash-locked'du (NumPy, pandas, scikit-learn).
- Orchestration `InputHandler` / `OutputHandler` mapping'leri Python task için çalışmıyordu.
- Tip deneyseldi ve varsayılan olarak kapalıydı; vnext-schema 0.0.58'e kadar type `23` şema enum'unda yoktu.

**Yeni Davranış:**
- `config.script` ve `config.executionMode` **reddedilir** (publish'te `TaskComponentValidator`, şemada `additionalProperties: false`).
- `config.handler` zorunludur (`^[A-Za-z_][A-Za-z0-9_.-]{0,127}$`); `config.input` ve `config.timeoutSeconds` (1–50, varsayılan 30) kalır.
- Handler'lar ve paketleri domain'in `FROM ghcr.io/burgan-tech/vnext/python-runtime:<sürüm>` ile build ettiği image'da yaşar. Orchestrator onu Dapr service invocation ile doğrudan çağırır (`POST v1/invoke`, kontrat `1`); Execution'a gidilmez.
- Standart `InputHandler` / `OutputHandler` mapping'i artık çalışır.
- Execution host hiçbir `Python:*` anahtarını okumaz; kalan override'lar yok sayılır. `python-runner` image'ı yerini `python-runtime` base image'ına bıraktı.
- Domain'de runtime yoksa (`Workflow:PythonRuntime:AppId` boş) her Python task'ı **çağrı yapılmadan `503`** ile düşer.

**Migration:**
1. Her Python script'ini domain'in runtime image'ında bir handler modülüne taşıyın: `def main(input)` → `@handler("isim")` ile işaretli bir fonksiyon (ör. `handlers/calculations.py`). Gerekli paketleri sabitlenmiş (tercihen hash'li) bir `requirements.txt`'e yazın — NumPy, pandas ve scikit-learn artık hazır gelmez.
2. Domain image'ını `FROM ghcr.io/burgan-tech/vnext/python-runtime:0.0.103` ile build edip registry'nize gönderin.
3. Helm values'ında `pythonRuntime`'ı açın (chart **1.0.127**): `pythonRuntime.enabled: true`, `pythonRuntime.image.repository` / `tag`. Chart orchestrator'a `Workflow__PythonRuntime__AppId`'yi kendisi verir.
4. Her type-`23` task tanımında `config.script` ve `config.executionMode`'u kaldırıp `config.handler` ekleyin; domain paketinin `@burgan-tech/vnext-schema` sürümünü **0.0.59**'a yükseltip `npm run validate` çalıştırın.
5. Girdiyi instance verisinden kuruyorsanız artık bir input mapping'iyle (`SetInput`) yapabilirsiniz; mapping yoksa task sonucu handler çıktısının kendisidir.
6. Execution override'larınızdan `Python:*` / `Python__*` anahtarlarını temizleyin.
7. Transition job bütçesinin (`WorkflowExecution:TransitionJobTimeoutSeconds`, varsayılan 300) akıştaki en uzun Python beklemesinin (`timeoutSeconds + TimeoutGraceSeconds`, en fazla 80 sn) üstünde olduğunu doğrulayın; bu ilişki başlangıçta denetlenmez.

Önce / sonra:

```json
// v0.0.102
"config": {
  "script": { "code": "def main(input):\n    return {'total': sum(input['values'])}", "type": "LOC", "encoding": "NAT" },
  "executionMode": "pythonNet",
  "input": { "values": [2, 3, 5] },
  "timeoutSeconds": 30
}

// v0.0.103
"config": {
  "handler": "sum_values",
  "input": { "values": [2, 3, 5] },
  "timeoutSeconds": 30
}
```

```python
# handlers/calculations.py (domain runtime image)
from vnext_runtime import handler

@handler("sum_values")
def sum_values(input):
    return {"total": sum(input["values"])}
```
